Límite WIP
Una columna llena no recibe más tareas. Cada límite se cambia desde el propio tablero.
Definición de Listo
Para empezar, la tarea necesita descripción clara, responsable y criterios de aceptación.
Definición de Hecho
Para cerrarla: código revisado, pruebas aprobadas y documentación al día. Entonces recibe su sello.
Columna vecina
Las tareas avanzan o retroceden de una en una. Ninguna etapa se salta.

Dos patrones de diseño sostienen cada movimiento.

Strategy

Cada regla es una clase con el mismo método validate(). El tablero solo pregunta; agregar una regla no lo modifica.

for (const policy of this.policies) {
  const reason = policy.validate(context);
  if (reason) throw new PolicyViolationError(reason);
}

Observer

El tablero publica cada cambio en un EventBus. La vista y el panel de avisos lo escuchan sin que el tablero sepa que existen.

8 eventos publicados, desde task:moved hasta wip:reached.

Qué pasa al pulsar la flecha de una tarjeta

  1. La vista pide el movimiento
  2. Cada política lo valida
  3. El tablero mueve la tarea
  4. Se publica el evento
  5. La interfaz se actualiza
